HA Finance Intelligence — Architecture

Self-contained visual companion to ha_finance_intelligence_spec.md and docs/context.md. Pure inline SVG — renders offline, no external scripts.

Legend: solid = core data path · dashed = optional / opt-in / external. The Markdown version (architecture.md) carries the same diagrams as Mermaid for GitHub.

1 · System 2 · Request flow 3 · Import & categorise 4 · Data model 5 · Deployment

1 · System & infrastructure

One container: React frontend → FastAPI → service layer → private SQLite. Everything external is opt-in.

Standalone (no Home Assistant): the same container runs behind an optional TLS reverse proxy instead of HA ingress — see reverse-proxy.md. Bind it to localhost or a header-stripping proxy (the app trusts X-Remote-User-*).

2 · Request flow

A read/write request, ingress → backend → service → SQLite and back.

3 · Import & categorisation flow

Two phases: upload → preview (dedup), then confirm → persist with the rules → vendor → keyword → FX pipeline per row.

4 · Data model — core spine

The full model has ~30 tables (spec §12); this shows the core relationships.

Other groups hang off the same ACCOUNT / TRANSACTION / USER spine: savings (SavingsBalance, SavingsGoal) · investments (AccountValue, Holding, HoldingPrice) · assets (Asset, AssetLog) · AI (AIRequest) · review (ReviewItem) · subscriptions · rules · budgets · tags · child allowance (ChildAllocation) · MFA (UserSession) · audit (AuditLog). Retention adds an archived_at column to transactions / receipts / AI-requests / audit-logs.

5 · Deployment — add-on image

Multi-stage build: the frontend is built with Node, then served by the Python runtime alongside the backend; data lives on a private volume.

Keep these in step with the code when a shape changes (a new external dependency, a new core entity, a changed flow). The source of truth is the code and the spec. · Mermaid source: architecture.md
